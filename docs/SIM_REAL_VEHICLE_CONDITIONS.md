# 실차 조건 인계서: 폐루프 시뮬레이터용 차량·센서 모델

작성 2026-10-02 · 출처 `krowd_stanley_control`의 dynamics sim (`vehicle_dynamics_sim_node.py`, `sim_sensors.py`, `bicycle_sim.py`)

## 3. 제어기와 주고받는 토픽

시뮬레이터에서는 같은 메시지를 `/simulation/*` 이름으로 쓴다.

| 실차 토픽 | 형식 | 단위·규약 |
|---|---|---|
| `/target_angle` (입력) | `std_msgs/Float32` | **컬럼(엔코더) 쪽 각도, rad.** 바퀴각이 아니다. 왼쪽 +. 조향 Teensy 펌웨어가 ±2.5 rad 넘는 명령은 거부한다 |
| `/target_speed` (입력) | `std_msgs/Float32` | **km/h.** ros_can_bridge가 ×100 해서 CAN 0x110으로 보낸다. m/s를 그대로 보내면 1/3.6 속도로 달린다 |
| `/brake` (입력) | `std_msgs/Bool` | true면 정지. 다시 출발하려면 false 뒤 속도 명령 |
| `/encoder` (출력) | `ros_can_bridge_msgs/EncoderAngleStamped` | `angle_rad`: 컬럼 쪽 실제 조향각, 50 Hz |
| `/ekf/odometry` (출력) | `nav_msgs/Odometry` | 100 Hz. `twist.linear.x` m/s, `twist.angular.z` rad/s (왼쪽 +) |
| `/ekf/heading_verified` (출력) | `std_msgs/Bool` (latched) | RTK course로 heading이 검증되면 true |

**주의: `/wheel_sensor`.** 2026-09-20 확인 당시 `speed_mps` 필드에 실제로는 km/h 값이 들어 있었습니다(3.6배). 그 뒤로 다시 확인하지 않았습니다. 속도는 `/ekf/odometry`를 쓰는 것이 안전합니다.

## 4. 조향 모델

### 4.1 명령 ↔ 바퀴각 (실측 조향표)

```
바퀴각 = interp(조향표, /target_angle − 영점)        영점 = −0.21 rad
```

- **영점(−0.21 rad):** 직진할 때의 엔코더 값입니다. 조향 Teensy 영점(`/steering_center`)을 다시 잡을 때마다 바뀌니, 세션마다 직진 bag에서 중앙값을 재야 합니다.
- **표 구성:** 측정한 왼쪽·오른쪽 타이어각을 Ackermann 관계 `cot δ = (cot δL + cot δR) / 2`로 등가 바퀴각 하나로 바꿉니다. 안쪽 네 줄은 `stanley_tuning_0922_235531`의 yaw rate와 속도에서, 양 끝은 9/19 손 측정에서 왔습니다.

| 영점 기준 명령 (rad) | 왼쪽 타이어 (°) | 오른쪽 타이어 (°) | 등가 바퀴각 (°) |
|---|---|---|---|
| −2.50 | −21.0 | −22.0 | −21.49 |
| −1.52 | −10.8 | −12.7 | −11.67 |
| −0.78 | −5.6 | −6.1 | −5.84 |
| 0.00 | 0.0 | 0.0 | 0.00 |
| +1.21 | +10.4 | +9.1 | +9.71 |
| +1.94 | +17.0 | +13.8 | +15.24 |
| +2.96 | +29.0 | +22.0 | +25.05 |

- **좌우 한계:** 명령은 영점을 더한 값으로 ±2.5 rad까지만 갑니다. 그래서 바퀴각은 오른쪽 −19.4°(회전반경 3.81 m), 왼쪽 +22.6°(3.21 m)가 한계입니다. 표가 비대칭이라 좌우가 다릅니다.
- **확인 결과:** 실주행에서 측정 바퀴각으로 계산한 회전이 실제 yaw rate와 0.95~0.98배로 맞았습니다(2026-09-26). 저속 슬립은 이 표에 이미 들어 있습니다.

### 4.2 조향 동특성

```
명령 → 0.24 s 지연 → 바퀴각이 최대 12°/s로 따라감 (바퀴 기준)
```

| 항목 | 값 | 근거 |
|---|---|---|
| 지연 | 0.24 s | `stanley_tuning_0922_235531`: `/target_angle` 대비 `/encoder` |
| 모터 속도 | 바퀴 기준 12°/s (엔코더 1.1~1.7 rad/s) | 명령이 0.5 rad 넘게 앞서 모터가 최대로 돌 때. 9/22, 9/24, 9/26 bag 세 개가 같음. **모터 최대 속도로 확인됨** |
| 오버슈트·백래시 | 모델에 없음 | |

- **영향:** 0°에서 19°까지 꺾는 데 약 1.6초가 걸립니다. 7 km/h면 그동안 3 m를 갑니다. 반경 4 m짜리 짧은 코너에서 바깥으로 밀리는 주된 원인입니다.
- **예전 값 주의:** 2026-09-26 전에는 40°/s를 썼는데, 이 값은 한 번 튄 값을 잘못 잡은 것이었습니다.

## 5. 구동 모델

```
실제 속도 목표 = /target_speed − 1.7 km/h × min(1, 목표 / 1.4 m/s)
그 목표로 가속 2.5 m/s², 감속 4.0 m/s²의 기울기로 따라감
```

| 항목 | 값 | 근거 |
|---|---|---|
| 속도 부족 | 1.7 km/h (1.4 m/s 아래에서는 비례로 줄어 0은 0) | `stanley_tuning_0922_235531`: 목표 8.1, 실제 6.5 km/h. 9/20에는 5 km/h 목표에 3.8 km/h |
| 가속 / 감속 | 2.5 / 4.0 m/s² | **가정** |
| `/brake` | 즉시 목표 0 | |

- **구동 MCU 특성:** 구동 MCU는 자체 PI로 속도를 맞추고, 목표가 낮아지면 스로틀만 줄입니다(브레이크 없음). 실제 감속은 타력 주행이라 4.0 m/s²보다 훨씬 느립니다. 경로 속도 프로파일은 0.5 m/s²로 가정하고 있습니다.
- **실차에서 관찰된 것:** `/brake`를 짧게(0.1~0.5 s) 넣었다 풀어도 차가 완전히 서서 3~6초 동안 출발하지 않았습니다(2026-09-24). 시뮬레이터에는 없는 동작입니다.

## 6. 위치 추정 모델 (ESKF 출력)

제어기가 받는 `/ekf/odometry`는 실제 위치에 아래 오차를 더한 값으로 만듭니다. 실제 위치는 TF와 RViz 표시에만 씁니다.

| 항목 | 모델 | 값 | 근거 |
|---|---|---|---|
| 위치 백색 잡음 | 매 주기 정규분포, 축마다 | 0.6 cm | 0922 bag `/ekf/odometry` 고주파 성분 (100 Hz, 185 s) |
| 위치 느린 오차 | 1차 Gauss-Markov, 축마다 | σ 7 cm, 상관시간 10 s | 실주행 ESKF와 RTK 위치 차이 5.4~7.9 cm/축 (9/24, 9/26 두 번) |
| yaw 잡음 | 매 주기 정규분포 | 0.14° | 0922 bag 고주파 성분 |
| yaw rate 잡음 | 매 주기 정규분포 | 0.58°/s | 0922 bag 고주파 성분 |
| 위치 튐 | 없음 | - | 0922 bag에서 5 cm 넘는 튐 0회 |
| 속도 | 실제 값 그대로 | - | |

```
느린 오차 갱신 (dt마다):  x ← a·x + N(0, σ²(1 − a²)),   a = exp(−dt / τ)
```

- **예전 값 주의:** 느린 오차는 2026-09-27까지 18 cm였습니다. ESKF 자체 공분산에서 잡은 상한이라, 직선에서 궤적이 ±0.3 m 물결치는 가짜 흔들림을 만들었습니다.

## 7. 조향 엔코더 모델

```
/encoder = round( (실제 바퀴각 → 조향표 역변환 + 영점) + N(0, 0.026²) , 0.01 rad )   50 Hz
```

| 항목 | 값 | 근거 |
|---|---|---|
| 주기 | 50 Hz | 실차 `/encoder` |
| 분해능 | 0.01 rad | 실차 `/encoder` |
| 떨림 | 0.026 rad | 0922 bag, 명령이 일정할 때 |

## 8. 출발 시 heading 검증 모델

실차 ESKF는 출발할 때 지난 세션에 저장한 heading으로 시작합니다. 직진 RTK course로 검증한 뒤에야 `/ekf/heading_verified`를 true로 냅니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 검증 조건 | GPS 5 Hz 표본이 3개 연속으로 속도 ≥ 1 m/s, \|yaw rate\| ≤ 0.10 rad/s, 표본 간격 ≤ 1 s, RTK Fixed | `krowd_sensors/config/gps_imu_eskf.yaml` |
| 검증 전 heading 오차 | 5° | **가정** |
| 검증 전 위치 오차 | 안테나 위치는 맞고 heading만 틀림 → `base_link`가 2 × 2.5038 × sin(오차/2)만큼 옆으로 밀림 (5°면 0.22 m) | ESKF 구조 |
| 검증 순간 | heading과 위치가 실제 값으로 점프 | |

**실차에서 본 heading 문제** (시뮬레이터에는 없음)
- 2026-09-21: 저장 heading이 124° 틀린 채 출발
- 2026-09-26 19:50: ESKF가 "검증됨" 상태로 122° 틀림. 위치도 안테나 거리만큼 4.4 m 어긋남
- 2026-09-26 20:41: MOLA 맵 로컬라이제이션이 90° 틀림. ESKF는 맞았음

## 9. 시뮬레이터에 없는 실차 현상 (한계)

1. **급코너에서 실차가 더 밀린다.** 같은 맵(20260923_113433, 반경 3.3~4.7 m 코너)에서 시뮬레이션의 코너 바깥 밀림은 0.2~0.5 m, 실차는 0.45~1.08 m였습니다. 조향 모터 속도를 넣은 뒤에도 2~2.5배 차이가 남습니다. 원인은 아직 모릅니다. 슬립과 조향표는 실차 bag에서 정상이었습니다.
2. **속도별 언더스티어:** 측정하지 않았습니다. 같은 코너를 속도를 바꿔 돈 bag이 필요합니다.
3. **구동 MCU 동특성:** 가속 응답, 타력 감속, brake 뒤 출발 지연, ASMS 대기가 없습니다.
4. **로컬라이제이션 고장:** RTK Float, ESKF가 GPS를 계속 거부하는 이탈(2026-09-23, 49 m), MOLA heading 오류가 없습니다.
5. **조향 영점의 세션별 변화:** 영점을 −0.21 rad로 고정했습니다. 실차는 세션마다 다릅니다(9/12 bag은 +0.08).
6. **센서 잡음 근거:** 위치·yaw 잡음과 엔코더 값은 bag 하나(`stanley_tuning_0922_235531`)에서 쟀습니다.
7. **고속:** 20 km/h 넘는 속도는 실차로 오래 달려 본 적이 없습니다.

## 10. 새 시뮬레이터에 옮길 때

- **그대로 가져다 쓸 수 있는 코드** (ROS 의존 없음, 단위 테스트 있음):

| 파일 | 내용 |
|---|---|
| `krowd_stanley_control/sim_sensors.py` | ESKF 잡음(Gauss-Markov 포함), 엔코더, RTK course 검증, 저장 heading 오차 모델 |
| `krowd_stanley_control/bicycle_sim.py` | 자전거 모델, `DelayedCommand`(조향 지연), `achieved_speed`(속도 부족) |
| `krowd_stanley_control/vehicle.py` | `steering_table`, `bicycle_angle_rad`, `SteeringActuator`(명령 ↔ 바퀴각, 좌우 한계) |
| `test/test_sim_sensors.py`, `test/test_bicycle_sim.py`, `test/test_steering_table.py` | 위 모델 테스트 |

- **차량 값 원본:** 조향표, 영점, 명령 한계는 `config/vehicle.yaml`에 있습니다. 값이 바뀌면 이 파일 기준으로 따릅니다.
- **참고 구현:** `krowd_stanley_control/vehicle_dynamics_sim_node.py`가 위 모델을 모두 묶은 노드입니다. `ideal: true`면 전부 끕니다.
- **현재 PP 패키지 상태:** `krowd_pp_stanley_control`과 `krowd_pp_stanleyff_control`의 시뮬레이터 사본에는 조향 지연과 속도 부족만 들어 있습니다. 조향 모터 속도, ESKF 잡음, 엔코더, heading 검증은 없습니다.
- **비교 방법:** 실차 조건을 넣은 결과와 이상 모델 결과를 함께 보면, 제어기 문제와 차량 조건 문제를 가를 수 있습니다.
